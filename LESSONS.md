# Lessons for KOML

The domain needs an explicit queue order, a supplied prior-send count, and a clear definition of a duplicate. Without these, a daily cap appears precise while different implementations approve different people. This build uses ordered evaluation and counts all earlier recipients, including blocked entries, conservatively.

The implementation assumption validated by synthetic tests is that deterministic input facts can reconcile exactly to planted approval and block decisions. Corrupting one fixture score changes the reason counts, demonstrating that the report computes its figures. The assumption that these rules improve Henry's real reputation remains untested; fixture correctness is not deliverability evidence.

Operating rule for future builds: specify the independent oracle and provenance before writing the engine, then deliberately change one input to prove the output is not hardcoded. Keep real-use adoption and error measurements separate from synthetic acceptance evidence.
